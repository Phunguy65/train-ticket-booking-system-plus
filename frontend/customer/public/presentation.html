Mỗi module (station, train, booking, payment) cùng cấu trúc 3 tầng

UC-01Đăng ký tài khoản
Actor: Khách hàng chưa có tài khoảnTiền điều kiện: Không

Luồng chính

  • Nhập email, password, fullName
  • Validate định dạng email, password ≥ 8 ký tự
  • Kiểm tra email chưa tồn tại
  • Hash password (BCrypt)
  • Tạo tài khoản với role CUSTOMER
  • Trả thông tin user (không có password)

Sequence Diagram

@startuml UC-01
title UC-01: Đăng ký tài khoản

actor "Khách hàng" as Actor
participant "Hệ thống" as API

Actor -> API: Register(email, password, fullName)
alt Dữ liệu đầu vào không hợp lệ
    API --> Actor: 400 + VALIDATION_ERROR
else Email đã tồn tại
    API --> Actor: 409 + USER_EMAIL_ALREADY_EXISTS
else Đăng ký thành công
    API -> API: Kiểm tra email chưa tồn tại
    API -> API: Băm mật khẩu, tạo tài khoản (CUSTOMER)
    API --> Actor: 201 + UserResponse(id, email, fullName, role, createdAt)
end
@enduml

Kiểm thử (12 tests)

UnitIntegrationStressSecurity
  • Đăng ký thành công với dữ liệu hợp lệ
  • Email trùng → 409 Conflict
  • Validation: format email, password ≥ 8 ký tự
  • SQL injection prevention
  • Stress: 50 concurrent registrations

UC-02Đăng nhập
Actor: Khách hàng có tài khoảnTiền điều kiện: Đã đăng ký (UC-01)

Luồng chính

  • Nhập email và password
  • Tìm user theo email
  • So sánh password (timing-safe BCrypt)
  • Tạo accessToken (JWT, 15 phút)
  • Tạo refreshToken (hash lưu DB)
  • Trả token pair + user profile

UnitIntegrationStressSecurityFE

  • Timing-safe (chống timing attack)
  • Chống user enumeration
  • Stress: 50 concurrent logins

UC-03Đăng xuất
Actor: Khách hàng bất kỳTiền điều kiện: Có refreshToken

Luồng chính (Idempotent)

  • Gửi refreshToken trong request body
  • Hash refreshToken (SHA-256)
  • Tìm token active trong DB
  • Đánh dấu token là REVOKED
  • Token đã revoked / không tồn tại → vẫn 200
  • Trả 200 OK trong mọi trường hợp hợp lệ

title UC-08: Đặt vé tàu

actor "Khách hàng" as Actor

== Tạo booking ==

Actor -> API: CreateBooking(scheduledTripId, seatIds, idempotencyKey)
alt Chưa xác thực
    API --> Actor: 401 Unauthorized
else Dữ liệu đầu vào không hợp lệ
    API --> Actor: 400 + VALIDATION_ERROR

    API --> Actor: 201 + BookingResponse (booking cũ)
else User không tồn tại
    API --> Actor: 404 + USER_NOT_FOUND

    API --> Actor: 409 + BOOKING_CANNOT_CONFIRM
else Scheduled trip không tồn tại
    API --> Actor: 404 + SCHEDULED_TRIP_NOT_FOUND
else Ghế không khả dụng
    API --> Actor: 409 + SEAT_NOT_AVAILABLE
else Tạo booking thành công
    API -> API: Tạo booking HELD, paymentDeadline = now + 15m
    API -> API: Hold seats (AVAILABLE -> HELD)
    API -> API: Publish BookingCreated event
    API --> Actor: 201 + BookingResponse(status=HELD)
end

== Thanh toán bất đồng bộ ==

Actor -> Stripe: Complete payment
alt checkout.session.completed

    API -> API: Confirm booking (HELD -> CONFIRMED)
    API -> API: Confirm seats (HELD -> BOOKED)
else payment_intent.payment_failed
    Stripe -> API: Webhook(payment failed)
    API -> API: Mark payment (PENDING -> FAILED)
end

  • All-or-nothing: không partial hold
  • Idempotency key → trả cùng kết quả
  • Ghế đã HELD/BOOKED → 409
  • Stress: 50 concurrent bookings cùng ghế

    API -> API: booking.cancel() HELD -> CANCELLED
    API -> API: releaseHeldSeats() HELD -> AVAILABLE
    API -> API: Publish events + SSE
    API --> Actor: 200 OK
else Hủy CONFIRMED (đã thanh toán)
    API -> API: booking.cancel() CONFIRMED -> CANCELLED
    API -> API: cancelBookedSeats() BOOKED -> CANCELLED
    API -> API: Publish events (requiresRefund=true) + SSE
    API --> Actor: 200 OK
end
@enduml

Kiểm thử

UnitIntegrationEvent
  • Hủy HELD booking thành công
  • Hủy CONFIRMED booking + refund flag
  • Booking đã cancelled → 409
  • Hủy booking người khác → 403
  • Seats released, SSE event phát ra

UC-12Thanh toán
Actor: Khách hàng có booking HELDTiền điều kiện: Đã đặt vé (UC-08)

Luồng chính

  • Tạo Stripe Checkout Session (bookingId, amount)
  • Trả checkoutUrl → redirect user đến Stripe
  • User thanh toán trên Stripe
  • Webhook: checkout.session.completed
  • Confirm: HELD→CONFIRMED, seats→BOOKED
  • Update payment: PENDING → PAID

Sequence Diagram

@startuml UC-12
title UC-12: Thanh toán

actor "Khách hàng" as Actor
participant "Hệ thống" as API
participant "Stripe" as Stripe

== Tạo phiên thanh toán ==

Actor -> API: CreateCheckout(bookingId)
alt Chưa xác thực
    API --> Actor: 401 Unauthorized
else Booking không tồn tại
    API --> Actor: 404 + PAYMENT_BOOKING_NOT_FOUND
else Booking không thuộc về khách hàng
    API --> Actor: 403 + ACCESS_DENIED
else Booking không ở trạng thái HELD hoặc đã hết hạn
    API --> Actor: 409 + PAYMENT_BOOKING_INVALID_STATE
else Payment đã được xử lý (PAID/REFUNDED)
    API --> Actor: 409 + PAYMENT_ALREADY_PROCESSED
else Đã có payment PENDING (idempotent)
    API --> Actor: 200 + CheckoutSessionResponse(paymentId, checkoutUrl, status=PENDING)
else Tạo checkout session thành công
    API -> Stripe: Create Checkout Session(amount, currency, successUrl, cancelUrl)
    Stripe --> API: sessionId, checkoutUrl
    API -> API: Tạo Payment(PENDING), lưu checkoutSessionId
    API --> Actor: 201 + CheckoutSessionResponse(paymentId, checkoutUrl, status=PENDING)
end

== Xử lý webhook ==

alt checkout.session.completed
    Stripe -> API: Webhook(completed, sessionId, paymentIntentId)
    API -> API: Confirm booking (HELD -> CONFIRMED)
    API -> API: Confirm seats (HELD -> BOOKED)
    API -> API: Mark payment (PENDING -> PAID)
else payment_intent.payment_failed
    Stripe -> API: Webhook(payment_failed)
    API -> API: Mark payment (PENDING -> FAILED)
else checkout.session.expired
    Stripe -> API: Webhook(expired)
    API -> API: Mark payment (PENDING -> CANCELLED)
else Payment đến muộn sau khi booking đã CANCELLED
    Stripe -> API: Webhook(completed)
    API -> Stripe: Create refund(paymentIntentId)
    API -> API: Mark payment REFUNDED
end
@enduml

Kiểm thử

UnitIntegrationWebhookRefund
  • Tạo checkout session thành công
  • Webhook completed → booking CONFIRMED
  • Webhook expired → payment FAILED
  • Duplicate webhook → idempotent
  • Late payment after cancel → auto refund
