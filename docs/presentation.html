Module nghiệp vụ (Bounded Context)

user station train booking payment shared

Mỗi module độc lập 3 tầng, giao tiếp qua Port — đảm bảo low coupling, high cohesion.

Tech Stack

Backend: Spring Boot 4.0, Java 25 Frontend: Next.js 16, React 19 DB: PostgreSQL 18 + Flyway Cache: Valkey 8.0 (Redis) Payment: Stripe SDK Realtime: Server-Sent Events

Lược đồ thực thể (ERD)

11 bảng — 5 phân hệ

User: users, refresh_tokens  ·  Station: stations  ·  Train: trains, coaches, seats, route_templates, scheduled_trips  ·  Booking: bookings, trip_seat_availability  ·  Payment: payments

UUID v7 PK · Soft delete · TIMESTAMPTZ (UTC) · Optimistic locking trên trip_seat_availability

UC-01Đăng ký tài khoản
Actor: Khách hàng chưa có tài khoảnTiền điều kiện: Không

Luồng chính

  • Nhập email, password, fullName
  • Validate định dạng email, password ≥ 8 ký tự
  • Kiểm tra email chưa tồn tại
  • Hash password (BCrypt)
  • Tạo tài khoản với role CUSTOMER
  • Trả thông tin user (không có password)

Sequence Diagram

Kiểm thử (12 tests)

UnitIntegrationStressSecurity
  • Đăng ký thành công với dữ liệu hợp lệ
  • Email trùng → 409 Conflict
  • Validation: format email, password ≥ 8 ký tự
  • SQL injection prevention
  • Stress: 50 concurrent registrations

UC-03Đăng xuất
Actor: Khách hàng bất kỳTiền điều kiện: Có refreshToken

Luồng chính (Idempotent)

  • Gửi refreshToken trong request body
  • Hash refreshToken (SHA-256)
  • Tìm token active trong DB
  • Đánh dấu token là REVOKED
  • Token đã revoked / không tồn tại → vẫn 200
  • Trả 200 OK trong mọi trường hợp hợp lệ

Sequence Diagram

Kiểm thử (12 tests)

UnitIntegrationStressSecurity
  • Logout thành công, token bị revoke
  • Idempotent: token đã revoked → 200
  • Idempotent: token unknown → 200
  • SQL injection prevention
  • Stress: 50 concurrent logouts

UC-12Thanh toán
Actor: Khách hàng có booking HELDTiền điều kiện: Đã đặt vé (UC-08)

Luồng chính

  • Tạo Stripe Checkout Session (bookingId, amount)
  • Trả checkoutUrl → redirect user đến Stripe
  • User thanh toán trên Stripe
  • Webhook: checkout.session.completed
  • Confirm: HELD→CONFIRMED, seats→BOOKED
  • Update payment: PENDING → PAID

Sequence Diagram

Kiểm thử

UnitIntegrationWebhookRefund
  • Tạo checkout session thành công
  • Webhook completed → booking CONFIRMED
  • Webhook expired → payment FAILED
  • Duplicate webhook → idempotent
  • Late payment after cancel → auto refund

Kết luận

Kết quả đạt được

  • Hoàn thành 12 use cases đầy đủ luồng chính + ngoại lệ
  • Kiến trúc Clean Architecture + DDD rõ ràng
  • Kiểm thử đa mức cho mỗi use case
  • Real-time seat updates qua SSE
  • Thanh toán an toàn qua Stripe webhook
  • Cơ chế giữ chỗ 15 phút + tự động hủy

Điểm nổi bật kỹ thuật

  • Idempotency cho đặt vé (tránh duplicate)
  • Cursor-based pagination (hiệu năng cao)
  • Domain Events cho loose coupling
  • Security: chống SQL injection, timing attack

Công nghệ

  • Backend: Spring Boot 4.0, Java 25, Virtual Threads
  • Frontend: Next.js 16, React 19, Bun
  • Database: PostgreSQL 18, Valkey 8.0
  • Payment: Stripe SDK
  • Infra: Docker Compose
